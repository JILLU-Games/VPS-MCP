## 3. Post-Update Feature Ledger (Updated After Each Phase)

* **After Phase 1 (2026-11-26):**
  - Fresh production containers (`NODE_ENV=production`) now auto-bootstrap a one-time setup token hash (`MCP_SETUP_TOKEN_HASH`) when no `admin.json` or `.env` hash is present, booting safely into First-Run Admin Setup instead of crashing (`BUG-01`).
  - Frontend `api()` in `public/panel.js` now automatically sends `x-session-token` when `state.sessionToken` is present and propagates `data.message` on API errors (`BUG-02`).
  - `cookieAttributes()` in `src/security/authentication.ts` now only sets `SameSite=None; Secure; Partitioned` when `x-forwarded-proto === 'https'` or `Origin` is `https://*.run.app`, keeping local HTTP `127.0.0.1` cookies as `SameSite=Strict` even behind local proxies (`BUG-07`).
  - Demo mode (`MCP_AUTH_MODE=demo`) now executes the exact same 64 MiB non-blocking `scrypt` password verification (`verifyPasswordNonBlocking`) and IP lockout engine as Production mode (`BUG-09`).
  - First-run setup form (`public/panel.html`) no longer pre-fills the forbidden 8-char `Pass@123` value (`BUG-10`).
* **After Phase 2 (2026-11-26):**
  - Removed fake `Auto-verified Gateway TLS` fallback (`BUG-03`): `checkTlsCertificate()` now validates actual TLS handshake on port 443, certificate expiration (`valid_to`), and hostname identity (`tls.checkServerIdentity()`), reporting accurate `active`, `pending`, or `failed` SSL status and diagnostic subtitles in the UI.
  - Added real DNS ownership & target verification (`BUG-04`): `checkDomainDnsAndSsl()` now checks that resolved IPs match the server's configured/detected IP, or CNAME points to the server/root domain, or the `_vpsmcp-challenge` TXT record contains the domain's unique `vpsmcp-verify=<token>` token.
  - Replaced hardcoded RFC 5737 `203.0.113.10` IP (`BUG-05`) with `MCP_PUBLIC_IP` (or non-internal IPv4 network interface detection).
  - Added multi-part public suffix TLD classification (`BUG-11`) so root domains like `example.co.uk` or `example.com.bd` are classified as `root` (`@`) and subdomains like `mcp.example.co.uk` are classified as `subdomain` (`mcp`).
  - `NetworkSettings.persist()` now throws `NetworkStorageError` on filesystem write failures and `POST /api/network/domains` returns HTTP `503 { error: 'network_storage_unavailable' }` instead of `400` (`BUG-12`).
* **After Phase 3 (2026-11-26):**
  - Added dynamic Host and Origin allowlist methods `network.isAllowedHost()` and `network.isAllowedOrigin()` in `src/security/network.ts` and connected them to `src/server/http.ts:124-137` (`BUG-06`). Any custom domain or subdomain added in the **Domain & SSL** panel is now immediately accepted for incoming HTTP/HTTPS requests, while unlisted domains remain rejected with `403 Invalid host` and removed domains lose routing access immediately.
* **After Phase 4 (2026-11-26 — All 4 Phases Complete):**
  - Integrated the isolated Unix socket broker process (`node dist/broker/main.js`) into `compose.yaml` with a shared `0700` private Unix socket volume (`mcp-socket:/run/vps-mcp`) and updated `scripts/install.sh` to auto-generate a 64-character `MCP_BROKER_SECRET` and `MCP_BROKER_SOCKET=/run/vps-mcp/broker.sock` (`BUG-08`). All 12 forensic audit bugs (`BUG-01` through `BUG-12`) are now resolved and verified across 67 automated tests.
